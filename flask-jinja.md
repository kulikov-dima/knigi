# Flask + Jinja2: шаблоны по шагам

В уроке 8 этапов (0–7), на каждом теория, примеры и несколько практических заданий. Все задания строят один проект — «Книжную полку». Данные лежат в файле **books.py**, готовое решение итогового задания — в **kniznaya-polka.zip**.

---

## Этап 0. Подготовка проекта

### Установка

```bash
mkdir kniznaya-polka
cd kniznaya-polka
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install flask
```

### Структура

Flask ищет шаблоны в папке `templates`, а файлы оформления (CSS, картинки) в папке `static`. Названия папок важны: если написать `template` без «s», Flask шаблон не найдёт.

```
kniznaya-polka/
├── app.py          ← код сервера
├── books.py        ← данные (скачайте файл)
├── templates/      ← HTML-шаблоны
│   └── index.html
└── static/         ← CSS, картинки
    └── style.css
```

### Первое приложение

```python
# app.py
from flask import Flask, render_template
from books import BOOKS

app = Flask(__name__)

@app.route("/")
def index():
    return render_template("index.html")

if __name__ == "__main__":
    app.run(debug=True)
```

```html
<!-- templates/index.html -->
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="utf-8">
  <title>Книжная полка</title>
</head>
<body>
  <h1>Книжная полка</h1>
</body>
</html>
```

### Что здесь происходит

1. Браузер открывает адрес `/`.
2. Flask находит функцию, у которой стоит `@app.route("/")`, и вызывает её.
3. `render_template("index.html")` берёт файл из `templates`, пропускает его через Jinja2 и возвращает готовый HTML.
4. Браузер получает обычный HTML. **Он ничего не знает о Jinja**: все `{{ }}` и `{% %}` исчезают ещё на сервере. Это легко проверить через «Просмотр кода страницы».

`debug=True` даёт две вещи: сервер сам перезапускается при сохранении файла, а при ошибке в браузере показывается подробная страница с её описанием. В настоящем проекте в интернете этот режим выключают.

## Этап 1. Переменные и выражения `{{ ... }}`

### Передача данных в шаблон

Данные попадают в шаблон через именованные аргументы `render_template`. Имя слева от `=` — это то, как переменная будет называться **в шаблоне**:

```python
@app.route("/")
def index():
    return render_template("index.html",
                           site_name="Книжная полка",
                           books_count=len(BOOKS),
                           first_book=BOOKS[0])
```

```html
<h1>{{ site_name }}</h1>
<p>Книг в каталоге: {{ books_count }}</p>
<p>Первая книга: {{ first_book.title }}</p>
```

### Что можно писать внутри `{{ }}`

**Строки и числа:**

```html
{{ site_name }}
{{ books_count }}
```

**Обращение к полям словаря.** Работают оба варианта, но первый короче и чаще используется:

```html
{{ first_book.title }}
{{ first_book["title"] }}
```

**Элементы списка по индексу:**

```html
{{ first_book.genres[0] }}     <!-- первый жанр -->
{{ first_book.genres[-1] }}    <!-- последний жанр -->
```

**Арифметика:**

```html
{{ 2026 - first_book.year }}        <!-- сколько лет книге -->
{{ first_book.pages / 30 }}          <!-- деление -->
{{ first_book.pages // 30 }}         <!-- целочисленное деление -->
{{ first_book.pages % 2 }}           <!-- остаток -->
```

**Сравнения** (выводят `True` или `False`, полезны в этапе 3):

```html
{{ first_book.rating > 4.5 }}
```

**Склейка строк** через `~` (тильда). Она сама превращает числа в строки:

```html
{{ first_book.title ~ " (" ~ first_book.year ~ ")" }}
<!-- Мастер и Маргарита (1967) -->
```

### Параметры из адреса

Часть адреса можно сделать переменной. `<int:book_id>` значит: «здесь будет целое число, передай его в функцию под именем `book_id`»:

```python
@app.route("/book/<int:book_id>")
def book(book_id):
    for b in BOOKS:
        if b["id"] == book_id:
            return render_template("book.html", book=b)
    return "Книга не найдена", 404
```

Теперь `/book/1`, `/book/2` и так далее показывают разные книги через один шаблон.

### Если переменной нет

Если написать в шаблоне `{{ boook.title }}` (с опечаткой), Jinja **не упадёт**, а выведет пустоту. Это удобно, но коварно: страница выглядит «почти нормально», а данных нет. Если что-то не выводится, первым делом проверьте написание имён в шаблоне и в `render_template`.

### Экранирование

Если в данных окажется текст `<b>привет</b>`, Jinja выведет его буквально, со скобками, а не жирным шрифтом. Это защита: пользователь не сможет вставить на сайт свой HTML или JavaScript. Пока просто запомните, что так и должно быть.

## Этап 2. Фильтры

Фильтр — это преобразование значения перед выводом. Пишется через вертикальную черту `|`:

```html
{{ значение | фильтр }}
{{ значение | фильтр(параметр) }}
```

### Фильтры для строк

```html
{{ "мастер и маргарита" | upper }}       <!-- МАСТЕР И МАРГАРИТА -->
{{ "МАСТЕР И МАРГАРИТА" | lower }}       <!-- мастер и маргарита -->
{{ "мастер и маргарита" | title }}       <!-- Мастер И Маргарита -->
{{ "мастер и маргарита" | capitalize }}  <!-- Мастер и маргарита -->
{{ "  текст  " | trim }}                  <!-- убирает пробелы по краям -->
{{ book.title | replace("и", "&") }}     <!-- замена -->
```

### Длинный текст: `truncate`

Обрезает текст до указанной длины и ставит `...` в конце:

```html
{{ book.description | truncate(100) }}
```

Особенность: Jinja не обрезает текст, если он длиннее лимита всего на несколько символов (по умолчанию до 5). Ещё он старается не резать слово посередине. Поэтому итоговая длина бывает чуть меньше указанной.

### Фильтры для списков

```html
{{ book.genres | length }}         <!-- количество элементов -->
{{ book.genres | join(", ") }}     <!-- роман, фантастика, сатира -->
{{ book.genres | first }}           <!-- первый элемент -->
{{ book.genres | last }}            <!-- последний элемент -->
```

`length` работает и для строк: `{{ book.title | length }}` — количество символов.

### Числа: `round`

```html
{{ 4.567 | round }}       <!-- 5.0 -->
{{ 4.567 | round(1) }}    <!-- 4.6 -->
```

### Значение по умолчанию: `default`

Если поля нет, выводится запасной вариант:

```html
{{ book.rating | default("нет оценки") }}
```

Откройте `/book/13`: у этой книги нет рейтинга, и вместо пустоты появится «нет оценки».

### Цепочки фильтров

Фильтры можно ставить один за другим. Они выполняются слева направо:

```html
{{ book.genres | join(", ") | upper }}
<!-- сначала список склеился в строку, потом строка стала заглавной -->

{{ book.description | truncate(60) | lower }}
```

### Фильтр в вычислениях

Фильтр относится к значению прямо перед ним. Если нужно применить его к результату выражения, используйте скобки:

```html
{{ (book.pages / 30) | round }}
```

## Этап 3. Условия `{% if %}`

### Два вида скобок

Пора запомнить главное различие:

- `{{ ... }}` — **вывести** значение на страницу;
- `{% ... %}` — **выполнить** команду (условие, цикл). Сама команда на страницу не попадает.

### Простое условие

```html
{% if book.rating >= 4.5 %}
  <p>Рекомендуем!</p>
{% endif %}
```

В отличие от Python, отступы в Jinja **ничего не значат**. Конец блока обозначается явно: `{% endif %}`. Если его забыть, будет ошибка `Unexpected end of template`.

### `elif` и `else`

```html
{% if book.pages > 500 %}
  <p>Толстая книга</p>
{% elif book.pages > 200 %}
  <p>Книга средней толщины</p>
{% else %}
  <p>Тонкая книга, прочтёте за вечер</p>
{% endif %}
```

### Логические операторы

Как в Python: `and`, `or`, `not`, `in`.

```html
{% if book.year < 1950 and book.rating > 4.5 %}
  <p>Проверенная временем классика</p>
{% endif %}

{% if "фантастика" in book.genres %}
  <p>🚀 Фантастика</p>
{% endif %}

{% if not book.genres %}
  <p>Жанр не указан</p>
{% endif %}
```

### Что считается «ложью»

Как и в Python, ложными считаются: пустой список `[]`, пустая строка `""`, `0`, `None` и отсутствующее значение. Поэтому `{% if book.genres %}` означает «если список жанров не пустой».

### Проверка, есть ли поле: `is defined`

```html
{% if book.description is defined %}
  <p>{{ book.description }}</p>
{% else %}
  <p>Описание скоро появится.</p>
{% endif %}
```

Есть и обратная форма: `is not defined`.

Зачем, если есть `default`? `default` подходит, когда надо вывести одно слово. Условие нужно, когда вместо значения показывается **другая разметка**: другой тег, другой класс, целый другой блок.

### Однострочное условие

Удобно для подстановки CSS-класса:

```html
<h1 class="{{ 'top' if book.rating >= 4.5 else '' }}">{{ book.title }}</h1>
```

Читается так: «вывести `'top'`, если рейтинг ≥ 4.5, иначе пустую строку».

### Осторожно с отсутствующими полями

У книги 13 нет рейтинга. Сравнение `book.rating >= 4.5` для неё вызовет ошибку. Безопасный вариант — сначала проверить наличие:

```html
{% if book.rating is defined and book.rating >= 4.5 %}
```

`and` проверяет условия слева направо и останавливается на первом ложном, поэтому до сравнения дело не дойдёт.

## Этап 4. Циклы `{% for %}`

### Основа

```html
<ul>
{% for book in books %}
  <li>{{ book.title }} — {{ book.author }}</li>
{% endfor %}
</ul>
```

Всё, что стоит между `for` и `endfor`, повторяется для каждого элемента. Внутри цикла можно использовать всё изученное: фильтры, условия, вложенные циклы.

### Пустой список: `else`

```html
{% for genre in book.genres %}
  <span class="tag">{{ genre }}</span>
{% else %}
  <span>Жанр не указан</span>
{% endfor %}
```

Блок `else` выполнится, только если список пустой. Это короче, чем писать отдельный `if`.

### Переменная `loop`

Внутри любого цикла есть специальная переменная `loop` со сведениями о текущем шаге:

| Что | Значение |
|---|---|
| `loop.index` | номер шага, начиная с 1 |
| `loop.index0` | номер шага, начиная с 0 |
| `loop.first` | `True` на первом шаге |
| `loop.last` | `True` на последнем шаге |
| `loop.length` | сколько всего элементов |
| `loop.revindex` | сколько осталось, включая текущий |
| `loop.cycle("a", "b")` | по очереди выдаёт `a`, `b`, `a`, `b`… |

Примеры:

```html
{% for book in books %}
  <p>{{ loop.index }} из {{ loop.length }}: {{ book.title }}</p>
{% endfor %}
```

Запятые между элементами, но не после последнего:

```html
{% for genre in book.genres %}
  {{ genre }}{% if not loop.last %}, {% endif %}
{% endfor %}
```

Таблица с чередующимися цветами строк:

```html
<table>
  <tr><th>№</th><th>Название</th></tr>
  {% for book in books %}
    <tr class="{{ loop.cycle('odd', 'even') }}">
      <td>{{ loop.index }}</td>
      <td>{{ book.title }}</td>
    </tr>
  {% endfor %}
</table>
```

### Вложенные циклы

У каждой книги список жанров, значит, цикл внутри цикла:

```html
{% for book in books %}
  <h3>{{ book.title }}</h3>
  {% for genre in book.genres %}
    <span class="tag">{{ genre }}</span>
  {% endfor %}
{% endfor %}
```

Внимание: во вложенном цикле `loop` относится к **внутреннему** циклу.

### Перебор словаря

```html
{% for key, value in book.items() %}
  <p>{{ key }}: {{ value }}</p>
{% endfor %}
```

### Фильтрация прямо в цикле

```html
{% for book in books if book.year < 1950 %}
  <li>{{ book.title }}</li>
{% endfor %}
```

Пропускаются книги, которые не подходят под условие. Сложную фильтрацию лучше делать в Python (этап 5), а в шаблоне оставлять простые случаи.

## Этап 5. Ссылки и `url_for`

### Проблема

Пока ссылки пишутся вручную:

```html
<a href="/book/1">Мастер и Маргарита</a>
<a href="/about">О сайте</a>
```

Представьте, что вы решили переименовать `/book/` в `/books/`. Придётся найти и исправить все ссылки во всех шаблонах. Какую-нибудь обязательно забудете, и она сломается.

### Решение

`url_for` строит адрес **по имени функции-обработчика**, а не по пути:

```python
@app.route("/about")
def about():                # имя функции — about
    ...
```

```html
<a href="{{ url_for('about') }}">О сайте</a>
<!-- в браузер придёт: <a href="/about">О сайте</a> -->
```

Если поменять декоратор на `@app.route("/info")`, ссылка сама станет `/info`. Шаблоны трогать не нужно.

Важно: в `url_for` передаётся **строка** с именем **функции**, а не путь. `url_for('/about')` — ошибка.

### Параметры пути

Если в роуте есть переменная часть, её значение передаётся именованным аргументом с тем же именем:

```python
@app.route("/book/<int:book_id>")
def book(book_id):
    ...
```

```html
<a href="{{ url_for('book', book_id=1) }}">Книга 1</a>
<!-- /book/1 -->

{% for b in books %}
  <a href="{{ url_for('book', book_id=b.id) }}">{{ b.title }}</a>
{% endfor %}
```

Если параметр забыть (`url_for('book')`), Flask выдаст ошибку `BuildError`: он не может собрать адрес без номера книги.

### Параметры запроса (то, что после `?`)

Если передать в `url_for` аргумент, которого **нет** в роуте, он попадёт в адрес после знака вопроса:

```html
{{ url_for('index', genre='фантастика') }}
<!-- /?genre=%D1%84%D0%B0... -->

{{ url_for('index', genre='роман', sort='year') }}
<!-- /?genre=роман&sort=year  (русские буквы будут закодированы) -->
```

`url_for` сам кодирует русские буквы и пробелы, поэтому вручную такие ссылки писать неудобно и опасно. Значения `None` в адрес не попадают — это пригодится, когда параметр то есть, то нет.

### Чтение параметров запроса в Python

Параметры после `?` читаются через `request.args`:

```python
from flask import request

@app.route("/")
def index():
    genre = request.args.get("genre")   # None, если параметра нет
    books = BOOKS
    if genre:
        books = [b for b in BOOKS if genre in b["genres"]]
    return render_template("index.html", books=books, current_genre=genre)
```

Чем параметры пути отличаются от параметров запроса:

| | Параметр пути | Параметр запроса |
|---|---|---|
| Пример | `/book/3` | `/?genre=роман` |
| В роуте | `<int:book_id>` | не указывается |
| В Python | аргумент функции | `request.args.get(...)` |
| Обязательный? | да | нет |
| Для чего | *какой* объект показать | *как* показать: фильтр, сортировка, страница |

### Статические файлы

Для файлов из папки `static` есть специальное имя `'static'` и параметр `filename`:

```html
<link rel="stylesheet" href="{{ url_for('static', filename='style.css') }}">
<img src="{{ url_for('static', filename='img/logo.png') }}">
```

Передадим из каждого роута, какая страница сейчас открыта:

```python
return render_template("index.html", books=BOOKS, active="index")
```

```html

<a href="{{ url_for('table') }}" class="{{ 'current' if active == 'table' else '' }}">Таблица</a>
```

## Этап 6. Наследование шаблонов

### Проблема

К этому моменту в каждом шаблоне повторяются `<!DOCTYPE>`, `<head>`, подключение CSS и меню. Чтобы добавить пункт меню, придётся менять все файлы.

### Идея

Делаем один **базовый шаблон** с общим каркасом и «дырками» — блоками. Остальные шаблоны говорят: «возьми базовый и заполни дырки вот этим».

```html
<!-- templates/base.html -->
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="utf-8">
  <title>{% block title %}Книжная полка{% endblock %}</title>
  <link rel="stylesheet" href="{{ url_for('static', filename='style.css') }}">
</head>
<body>
  <nav>
    <a href="{{ url_for('index') }}">Карточки</a>
    <a href="{{ url_for('table') }}">Таблица</a>
    <a href="{{ url_for('about') }}">О сайте</a>
  </nav>

  <main>
    {% block content %}{% endblock %}
  </main>

  <footer>{% block footer %}Учебный проект{% endblock %}</footer>
</body>
</html>
```

```html
<!-- templates/about.html -->
{% extends "base.html" %}

{% block title %}О сайте — Книжная полка{% endblock %}

{% block content %}
  <h1>О сайте</h1>
  <p>Учебный каталог книг.</p>
{% endblock %}
```

### Как это работает

1. Flask рендерит `about.html`, видит `extends` и берёт за основу `base.html`.
2. В `base.html` на место `{% block title %}` подставляется содержимое одноимённого блока из `about.html`.
3. Блок `footer` в `about.html` не задан, поэтому остаётся то, что написано в `base.html` («Учебный проект»). Это значение по умолчанию.

### Правила

- `{% extends %}` — **первая строка** дочернего шаблона.
- Всё, что в дочернем шаблоне написано **вне** блоков, игнорируется. Частая ошибка: написать текст после `extends`, но до `{% block %}`, и удивляться, что он не виден.
- Имена блоков в родителе и потомке должны совпадать.
- Блоков может быть сколько угодно, и их порядок в дочернем шаблоне не важен.
- Переменные из `render_template` видны и в дочернем, и в базовом шаблоне. Поэтому подсветка меню с `active` работает прямо в `base.html`.

### `super()` — дополнить, а не заменить

```html
{% block footer %}
  {{ super() }} · Страница книги
{% endblock %}
<!-- Учебный проект · Страница книги -->
```

### Блок для «своего» CSS

Полезный приём: оставить в `<head>` пустой блок, чтобы отдельные страницы могли добавить свои стили:

```html
<head>
  ...
  {% block extra_head %}{% endblock %}
</head>
```

## Этап 7. `include` — вставка фрагментов

### Зачем

Наследование отвечает за **каркас страницы**. Но бывают куски, которые повторяются **внутри** разных страниц: карточка книги, меню, подвал. Их удобно держать в отдельных файлах и вставлять через `include`.

```html
{% include "partials/nav.html" %}
```

Папка `partials` — просто договорённость: туда складывают фрагменты, которые сами по себе страницами не являются.

### Видимость переменных

Вставленный шаблон видит все переменные из того места, где стоит `include`. Включая переменную цикла:

```html
<!-- templates/partials/book_card.html -->
<article class="card">
  <h3><a href="{{ url_for('book', book_id=book.id) }}">{{ book.title }}</a></h3>
  <p>{{ book.author }}, {{ book.year }}</p>
</article>
```

```html
<!-- templates/index.html -->
{% for book in books %}
  {% include "partials/book_card.html" %}
{% endfor %}
```

Внутри `book_card.html` нет никакого цикла, но `book` там доступна: её «принёс» цикл из `index.html`. Отсюда важное следствие: имя переменной должно совпадать. Если в `index.html` написать `{% for b in books %}`, карточка будет пустой — она ждёт именно `book`.

### `extends` или `include`

| | `extends` | `include` |
|---|---|---|
| Смысл | «я — вариант этой страницы» | «вставь сюда этот кусок» |
| Где стоит | первая строка | в любом месте, хоть в цикле |
| Сколько раз | один на шаблон | сколько угодно |
| Пример | все страницы на основе `base.html` | меню, карточка, подвал |

Они отлично работают вместе: `base.html` сам подключает `nav.html` и `footer.html` через `include`.

## Шпаргалка

| Синтаксис | Для чего |
|---|---|
| `{{ x }}` | вывести значение |
| `{% ... %}` | команда: условие, цикл, наследование |
| `x.field`, `x[0]` | поле словаря, элемент списка |
| `a ~ b` | склеить строки |
| `x \| upper` | применить фильтр |
| `x \| default("—")` | запасное значение |
| `x is defined` | проверить, есть ли значение |
| `'a' if cond else 'b'` | однострочное условие |
| `{% for %} ... {% else %} ... {% endfor %}` | цикл с вариантом для пустого списка |
| `loop.index`, `loop.first`, `loop.last` | данные о шаге цикла |
| `url_for('func')` | ссылка на страницу по имени функции |
| `url_for('func', id=1)` | ссылка с параметром пути |
| `url_for('func', genre='x')` | ссылка с параметром `?genre=x` |
| `url_for('static', filename='a.css')` | ссылка на статический файл |
| `request.args.get('x')` | прочитать `?x=` в Python |
| `{% extends "base.html" %}` | унаследовать каркас |
| `{% block name %}{% endblock %}` | заполняемая часть каркаса |
| `{{ super() }}` | содержимое блока родителя |
| `{% include "partials/x.html" %}` | вставить фрагмент |
